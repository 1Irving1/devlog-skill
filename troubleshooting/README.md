# 트러블슈팅 기록

깨진 것을 고친 과정. **답이 아니라 좁혀 간 경로**가 본체다.
원인을 못 찾은 것도 쓴다 — 미해결 기록이 다음 번 시작점이 된다.

기준: **틀린 가설이 몇 개 적혀 있는가.** 한 방에 맞춘 기록은 대개 사후 각색이다.

## 명명

`YYYY-MM-DD-kebab-case-symptom.md` — 원인이 아니라 **증상**으로 짓는다.
겪을 때는 원인을 모르고, 다시 찾을 때도 증상으로 찾는다.
예: `2026-08-28-mcp-tools-not-loaded.md`

## 형식

### 1. 증상
관측된 사실만. 에러 메시지 원문, 스택트레이스, 로그, 스크린샷.
**추측을 섞지 않는다** — "~때문에 보이는 듯"은 여기가 아니라 3번.

### 2. 환경
언제, 어디서, 무엇이. 브랜치·커밋 SHA, 컨테이너·이미지 태그, OS, 버전.
재현 조건(항상 / 특정 순서에서만 / 간헐)도.
**소요 시간**을 적는다 — 처음 관측부터 조치까지. 자소서에서 정직한 숫자가 되고, 안 적으면 기억에 남지 않는다.

### 3. 추적
시간순으로. 각 단계는 **가설 → 확인 방법 → 결과 → 기각 또는 진전**.

```
가설 1: MCP 서버 미등록
확인:   claude mcp list
결과:   ✔ Connected — 기각. 등록은 됐고 세션이 못 읽는 것
```

기각된 가설을 지우지 않는다. 그게 이 문서의 값어치다.

### 4. 원인
확정된 근본 원인 한 문단. **확정 못 했으면 "미확정"이라 쓰고 남은 후보를 적는다.**

### 5. 조치
실제로 한 것. 임시 우회면 임시라고 명시하고, 제대로 된 해결은 무엇인지 적는다.

### 6. 재발 방지
같은 걸 또 겪지 않으려면 무엇이 바뀌어야 하나 — 테스트, 알림, 문서, 설정.
"조심한다"는 재발 방지가 아니다. 할 게 없으면 `없음`.

### 7. 남은 의문
왜 그렇게 동작하는지 아직 모르는 부분. 없으면 `없음`.
