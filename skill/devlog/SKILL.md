# devlog — 개인 개발 기록

기록은 `~/Desktop/penguin-devlog/`에 있다. 프로젝트 레포가 아니다 — **거기에 쓰지 말 것.**
블로그·자소서에서 그대로 인용할 단위이므로 각색하지 않는다.

## 순서

1. **폴더를 고른다** (아래 표). 애매하면 사용자에게 묻는다
2. **같은 주제 파일이 이미 있는지 `ls`로 본다.** 있으면 새로 만들지 않고 갱신한다
   (review 덧붙임 · troubleshooting 미확정→확정 · adr 대체)
3. **`~/Desktop/penguin-devlog/README.md`와 해당 폴더의 `README.md`를 읽는다.**
   형식 명세는 거기에 있다. 기억으로 쓰지 않는다 — 형식은 갱신된다
4. **쓰기 전에, 사용자만 아는 것을 한 번에 묶어서 묻는다** — 계기, 당시 판단, 소요 시간, 남은 의문.
   쓰고 나서 물으면 이미 추정으로 채운 뒤다
5. 그 형식대로 파일을 쓴다. frontmatter(`date` / `tags` / `related`)부터
6. **폴더 README의 `## 인덱스`에 한 줄 추가한다.** 형식은 루트 README. 빠뜨리기 쉽다

## 폴더 고르기

| 사용자가 말하는 것 | 폴더 | 파일명 |
|---|---|---|
| 왜 이렇게 하기로 했는지 | `adr/` | `NNNN-kebab-title.md` — 번호는 폴더 안 파일명 마지막 +1 |
| 뭘 세웠고 어떻게 띄웠는지 | `infra/` | `YYYY-MM-DD-kebab.md` |
| 뭘 구현했는지 | `backend/` | `YYYY-MM-DD-kebab.md` |
| 뭐가 깨졌고 어떻게 고쳤는지 | `troubleshooting/` | `YYYY-MM-DD-증상.md` (원인 아님) |
| 이 코드가 왜 이렇게 도는지 | `review/` | `kebab-주제.md` (날짜 아님) |

한 기록에 두 성격이 섞이면 쪼갠다. 결정이 튀어나오면 `adr/`로 빼고 원래 문서엔 `ADR-NNNN` 링크만.

## 놓치기 쉬운 것

- **실물을 붙인다.** 명령·로그·에러·코드는 원문 그대로. 요약하면 값어치가 없어진다.
  세션 기록에 남아 있으면 거기서 그대로 가져온다. 셸(`# pwsh` / `# bash`) 표기
- **실패를 지운 채로 쓰지 않는다.** 기각된 가설, 되돌린 조치, 몰랐던 문법이 본체다.
  한 번에 맞춘 것처럼 정리하면 안 된다
- **`review/`의 질문은 대화 원문 그대로.** 사용자가 이 세션에서 실제로 친 문장을 — 오타·어설픈 추측 포함 —
  다듬지 않고 옮긴다. 아직 묻지 않은 상태면 추적 전에 먼저 묻는다. 내가 답을 알아도 질문을 대신 지어내지 않는다
- **1인칭 과거형.** "나는 ~했다". 규칙 설명만 현재형
- 비밀값은 `<REDACTED>`
- 팀 문서는 Cushion `penguin-milk/`에 있다 (`cushion` 스킬). 참조는 `팀 ADR-NNNN` / `Cushion arch/infra.md §4` 꼴
