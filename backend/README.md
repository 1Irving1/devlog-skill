# 백엔드 구현 기록

Spring Boot 애플리케이션 코드를 **무엇을 어떻게 만들었나**의 기록.
결정(`adr/`)과 이해(`review/`) 사이에 있다 — 내가 짠 코드의 구현 과정.

기준: **이 문서를 읽은 사람이 코드를 열지 않고도 설계를 설명할 수 있는가.**

## 명명

`YYYY-MM-DD-kebab-case-title.md` — 기능·모듈 단위. 예: `2026-09-02-order-execution.md`

## 형식

### 1. 요구
무엇을 만들어야 했나. 근거가 되는 스펙 경로(`specs/003-trading/spec.md FR-012`,
`Cushion spec/features.md §6`)를 적는다. MR 번호(`!12`)와 브랜치는 frontmatter `related`에. 요구가 애매했으면 어떻게 좁혔는지도.

### 2. 설계
클래스·계층·데이터 흐름. 다이어그램이든 목록이든.
**선택지가 있었던 지점을 표시한다** — 그중 근거를 남길 만한 게 있으면 `ADR-NNNN`으로 빼고 링크.

### 3. 구현
핵심 코드 조각만. 전체 파일을 붙이지 않는다.
각 조각에 **왜 이렇게 썼는지** 한 줄씩. 인용에는 `파일:라인`을 붙인다.

### 4. 테스트
무엇을 어떻게 검증했나. 테스트 이름과 그것이 **깨뜨리려는 가정**을 함께 쓴다.
안 쓴 테스트가 있으면 왜 안 썼는지.

### 5. 배운 것
이 구현으로 처음 알게 된 것. 문법·프레임워크 동작이면 `review/`로 빼고 링크.

### 6. 남은 의문
리팩터링 후보, 성능 미확인 구간, 스펙과 어긋날 소지. 없으면 `없음`.
