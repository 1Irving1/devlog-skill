# 코드 리딩 기록

내가 짜지 않았거나, 짰어도 **왜 그렇게 도는지 모르는** 코드를 읽고 남기는 기록.
남의 코드·라이브러리·프레임워크 내부·팀원 MR·과거의 내 코드가 대상이다.

두 종류의 궁금증을 다룬다:
- **순서** — 이게 언제 불리고, 무엇을 거쳐, 어디서 끝나는가
- **문법** — 이 표현이 무슨 뜻이고 왜 이 자리에 쓰였는가

기준: **질문을 먼저 박제했는가.** 답을 알고 난 뒤 쓴 질문은 이미 질문이 아니다.

## 명명

`kebab-case-topic.md` — 날짜가 아니라 **주제**로. 다시 찾을 때 날짜를 기억하지 못한다.
예: `transactional-self-invocation.md`, `kafka-consumer-rebalance.md`

한 파일에 같은 주제의 질문을 계속 덧붙여도 된다. 다른 주제면 새 파일.

## 형식

### 1. 대상
읽은 코드의 위치. `파일:라인`, 커밋 SHA, 라이브러리면 버전까지.
읽게 된 계기 한 줄 (버그 추적 중 / MR 리뷰 / 그냥 궁금해서).

### 2. 질문
**읽기 전에, 모르는 상태로 쓴다.** 번호를 붙여 나열.
"대충 이런 것 같은데 맞나" 수준의 어설픈 추측도 그대로 남긴다 — 나중에 대조하면 그게 학습 기록이다.

```
Q1. @Transactional이 붙은 메서드를 같은 클래스에서 부르면 왜 트랜잭션이 안 걸리나
Q2. 프록시라는 게 정확히 어느 시점에 끼어드나
```

### 3. 추적
호출 순서를 실제로 따라간 경로. 진입점 → 중간 → 종료.
어디서 무엇을 보고 알았는지(디버거 / 로그 / 소스 / 문서)를 함께 적는다.

```
1. Controller.order()          OrderController.java:42
2. → OrderService.execute()    프록시 경유 ← 여기서 트랜잭션 시작
3. → this.validate()           프록시 우회 ← Q1의 답
```

### 4. 문법 메모
처음 본 표현·관용구. **무엇을 하는가**와 **왜 여기서 그걸 쓰는가**를 나눠 쓴다.
비슷한데 다른 것(`==` vs `equals`, `map` vs `flatMap` 류)이 있으면 대조표.

### 5. 답
2번의 질문 번호에 하나씩 대응시켜 답한다. 못 푼 건 `미해결`.
답을 확인한 근거(공식 문서 링크, 실험 코드와 그 출력)를 붙인다.
실험 코드는 **본문에 전체를 인라인**한다. scratchpad나 지운 브랜치를 가리키면 재현 불가다.

### 6. 남은 의문
읽다가 새로 생긴 질문. 여기가 다음 문서의 2번이 된다. 없으면 `없음`.
