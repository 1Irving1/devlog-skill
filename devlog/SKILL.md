# devlog — 개인 개발 기록

기록은 개인 기록 레포 `dev-journal`에 남긴다. **작업 중인 프로젝트 레포에 쓰지 말 것** —
개인 기록이고 팀에 공유되지 않는다.

블로그·자소서에서 그대로 인용할 단위이므로 각색하지 않는다.

## 어디에 쓰나

```
<dev-journal>/projects/<프로젝트명>/
```

`<dev-journal>`은 보통 `~/Desktop/dev-journal`. 없으면 `~`, `~/Documents`도 본다.
`<프로젝트명>`은 지금 작업 중인 프로젝트에 해당하는 폴더 — `ls`로 확인하고,
어느 것인지 확실하지 않으면 **묻는다.** 새 프로젝트면 아래 "새 프로젝트" 참고.

레포를 못 찾으면 만들지 말고 사용자에게 알린다 (클론하지 않은 PC일 수 있다).

## 순서

1. **프로젝트 폴더를 찾는다** (위)
2. **폴더를 고른다** (아래 표). 애매하면 사용자에게 묻는다
3. **같은 주제 파일이 이미 있는지 `ls`로 본다.** 있으면 새로 만들지 않고 갱신한다
   (review 덧붙임 · troubleshooting 미확정→확정 · adr 대체)
4. **형식 명세를 읽는다** — 프로젝트 폴더의 `README.md`와 해당 하위 폴더의 `README.md`.
   **기억으로 쓰지 않는다.** 형식은 프로젝트마다 다르고 갱신된다.
   `_template.md`가 있으면 그것을 따른다
5. **쓰기 전에, 사용자만 아는 것을 한 번에 묶어서 묻는다** — 계기, 당시 판단, 소요 시간, 남은 의문.
   쓰고 나서 물으면 이미 추정으로 채운 뒤다
6. 그 형식대로 파일을 쓴다
7. **인덱스가 있으면 한 줄 추가한다** (폴더 README의 `## 인덱스`)
8. **커밋·push한다.** 커밋 타입은 `docs`. 문서 하나 끝나면 바로 올린다

## 폴더 고르기

프로젝트마다 폴더 구성이 다를 수 있다. 실제 `ls` 결과를 우선하고, 아래는 통상 대응이다.

| 사용자가 말하는 것 | 폴더 | 파일명 |
|---|---|---|
| 왜 이렇게 하기로 했는지 | `adr/` (또는 `개인_adr/`) | `NNNN-kebab.md` — 번호는 폴더 안 파일명 마지막 +1 |
| 뭘 세웠고 어떻게 띄웠는지 | `infra/` | `YYYY-MM-DD-kebab.md` |
| 뭘 구현했는지 | `backend/` `frontend/` | `YYYY-MM-DD-kebab.md` |
| 뭐가 깨졌고 어떻게 고쳤는지 | `troubleshooting/` | `YYYY-MM-DD-증상.md` (원인 아님) |
| 이 코드가 왜 이렇게 도는지 | `review/` | `kebab-주제.md` (날짜 아님) |
| 남이 준 자료·외부 문서 | `reference/` | 원본 이름 유지 |

한 기록에 두 성격이 섞이면 쪼갠다. 결정이 튀어나오면 `adr/`로 빼고 원래 문서엔 `ADR-NNNN` 링크만.

## 놓치기 쉬운 것

- **실물을 붙인다.** 명령·로그·에러·코드는 원문 그대로. 요약하면 값어치가 없어진다.
  세션 기록에 남아 있으면 거기서 그대로 가져온다. 셸(`# pwsh` / `# bash`) 표기
- **실패를 지운 채로 쓰지 않는다.** 기각된 가설, 되돌린 조치, 몰랐던 문법이 본체다.
  한 번에 맞춘 것처럼 정리하면 안 된다
- **`review/`의 질문은 대화 원문 그대로.** 사용자가 세션에서 실제로 친 문장을 — 오타·어설픈 추측 포함 —
  다듬지 않고 옮긴다. 아직 묻지 않은 상태면 추적 전에 먼저 묻는다. 내가 답을 알아도 질문을 대신 지어내지 않는다
- **1인칭 과거형.** "나는 ~했다". 규칙 설명만 현재형
- **모르는 건 채우지 않는다.** 추정으로 메우면 각색이다
- 비밀값·토큰·키는 `<REDACTED>`
- 팀 문서를 참조할 땐 출처와 경로를 적는다 (`팀 ADR-0001`, `Cushion arch/infra.md §4`, `MR !12`, 커밋 SHA)

## 새 프로젝트

프로젝트 폴더가 없으면 **기존 프로젝트 폴더의 구조와 형식 README를 복사해 시작한다.**
어느 프로젝트를 본으로 삼을지 사용자에게 묻는다. 형식을 새로 지어내지 않는다.
