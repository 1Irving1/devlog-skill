# 인프라 기록

Docker·Kafka·PostgreSQL·Redis·Nginx·CI/CD 등 **인프라를 세우고 운영한 작업**을 남긴다.
판단이 아니라 작업이다 — "왜 Kafka인가"는 `adr/`, "Kafka를 어떻게 띄웠나"는 여기.

기준: **6개월 뒤의 내가 이 문서만 보고 똑같이 재현할 수 있는가.**

## 명명

`YYYY-MM-DD-kebab-case-title.md` — 작업일 기준. 예: `2026-08-28-jenkins-migration.md`

## 형식

### 1. 목표
무엇을 세우려 했나. 한두 문장. 이 작업 전에 없었던 것.

### 2. 구성
결과물의 형태 — 서비스·포트·볼륨·네트워크·토픽·인덱스 등. 표나 다이어그램.
팀 스펙(`Cushion arch/infra.md`)과 다르게 갔으면 그 차이를 명시한다.

### 3. 실행
**실제로 친 명령과 실제 설정 파일**을 순서대로. 손으로 다듬지 말 것.
셸 표기(`# pwsh` / `# bash`)와 설정 파일 "변경 부분만" 규칙은 루트 README를 따른다.
중간에 실패했으면 실패한 명령도 남기고 무엇을 바꿔 통과했는지 이어 쓴다.

### 4. 검증
동작을 확인한 방법과 **그 출력**. `curl` 응답, `docker ps`, `kafka-topics --describe`,
헬스체크 결과 등. "잘 됐다"는 검증이 아니다.

### 5. 걸린 것
막혔던 지점과 우회. 원인 추적이 길어지면 `troubleshooting/`으로 빼고 여기선 링크.

### 6. 남은 의문
운영에 들어가면 다시 봐야 할 것, 아직 이해 못 한 설정값. 없으면 `없음`.
